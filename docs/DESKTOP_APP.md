# 桌面应用与安装验收

应用与公开仓库名称为 chat-bot。当前首版目标：Windows x64 的 NSIS EXE，macOS x64/arm64 的 DMG 与更新 ZIP，Ubuntu24.04 x64 的 deb 与 AppImage。

Windows 使用可选择程序安装目录的安装向导，支持中文和空格路径。配置、聊天数据和下载组件仍保存在当前用户的应用数据目录，重新选择程序安装位置会保留这些数据。

## 程序与数据

Electron 仅承载界面、受控桌面操作和更新。独立 Node24 后端启动现有 Fastify、SQLite 与聊天 worker。只读后端、脚本和原生依赖位于程序 resources 中，用户配置、数据库、素材及组件在 Electron userData 的 chat-bot 目录。现有项目目录和命令行入口保留，不自动导入原项目私人数据。

首次使用依次准备组件、本人登录模型、配置 QQ 号和管理密码，再打开连接与诊断完成 QQ 扫码。已有 NapCat 账号配置不会被覆盖，需在连接设置中核对现有 OneBot 令牌。macOS 官方安装器可能写入外部 QQ 容器，这些外部数据不会被本应用的卸载清理删除。

关闭窗口继续托盘运行。退出和安装更新先停止接收新任务、等待任务收尾，再保存是否可正常恢复；崩溃、人工暂停和不明发送状态不自动恢复，也不重发。

桌面管理服务优先使用本机3210端口；旧版网页管理台或其他程序占用时自动选择空闲回环端口，窗口与安全校验跟随实际端口，不会关闭占用端口的程序。已配置的 Tailscale 私人访问会在启动时更新到本次管理端口。

升级保留数据。Windows 卸载器可选择是否清除本应用数据；macOS/Linux 使用应用内卸载与数据清理，再按系统方式移除程序。直接删除程序默认保留数据。外部模型账号、QQ数据和服务历史需在对应软件管理。

## 更新与空间任务

使用 electron-updater 与 GitHub Releases。自动检查并下载，用户确认后等待任务结束再重启安装。正式包必须完成 Windows 签名、macOS签名与公证，并执行旧版到新版的真实更新验收。测试构建不能宣称已完成正式更新上线。

空间任务每天北京时间18:00触发，共享已有每日去重记录；未运行、暂停、失败或结果不明均不补发。启用前检查并关闭同账号的其他定时发布。私人远程访问为可选项，先在官方 Tailscale 完成本人登录，再选择配置私人访问，不启用公开 Funnel。

## 发布门禁与验收

先通过本地脱敏复核，再运行固定版本 ggshield。首次公开使用审查后的源码快照创建新公开历史，避免把原有私人 Git 作者身份或历史资料一并公开。每次后续发布核对全量拟公开历史、当前源码、文档、截图、测试数据，以及最终安装包解包后的应用资源与元数据。

GitGuardian检查必须对每个预期文本分块返回结果。仅退出码0或零命中而缺失扫描实体不算通过。二进制、图片及第三方署名需另外人工复核；第三方必须保留的许可与公开署名不能当作私人信息直接删去。发现真实凭据先阻断发布，清除并处理该凭据后重新审查，不能只加入忽略列表。

GitHub Secrets 至少配置 GITGUARDIAN_API_KEY；正式签名再配置平台签名与公证凭据。缺少条件时流水线必须停止，不能跳过。人工复核记录需要绑定源码清单摘要与最终安装包SHA256，每次内容变化后重新复核。

验收分别记录：构建成功、CI与模拟服务测试、各目标平台实机登录和真实收发。真实 QQ 测试只能使用明确指定的测试账号与收件目标；未实测的平台标为待验收。不得将模拟成功写成真实QQ送达。
